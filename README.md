# aboutme

Мой личный сайт на [koppa0.dev](https://koppa0.dev): кто я, чем занимаюсь, мои пет-проекты.

У сайта две темы, светлая и тёмная, и два языка, русский и английский. Ещё на нём есть:
- терминал (открывается клавишей `/`);
- таймлайн;
- стек в виде падающих капсул, которые можно бросать мышкой;
- плеер «сейчас играет».

Тексты, проекты и цвета меняются в админке, не трогая код.

## Из чего сделан

| Часть | Что внутри |
|---|---|
| Страница | Обычные HTML, CSS и JS, без сборщиков. Лежит в `nginx/html/`. |
| API | Python 3.13 и FastAPI. Код в `app/`. |
| База | Postgres 16: тексты, проекты, тема, пользователи. |
| Сервер | nginx: раздаёт страницу, проксирует `/api` в FastAPI, держит HTTPS. |
| Запуск | Docker Compose, три контейнера: `nginx`, `api`, `postgres`. |

Наружу открыт только nginx. Api и Postgres доступны только внутри сети Docker.

## Запустить у себя

Нужен только Docker.

```bash
cp .env.example .env
```

В `.env` поменяй пароль базы и `SESSION_SECRET`. Секрет — длинная случайная строка, с заглушкой из примера вход в админку не заработает. Сгенерировать его можно так:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

Запуск:

```bash
docker compose -f docker-compose.yml -f docker-compose.local.yml up --build
```

Сайт откроется на http://localhost:8080. Работает ли api, проверяет `curl http://localhost:8080/api/health`, ответ должен быть `{"status":"ok","database":"ok"}`.

Остановка:

```bash
docker compose -f docker-compose.yml -f docker-compose.local.yml down
```

Файл `docker-compose.local.yml` нужен только для своего компьютера: он вешает сайт на порт 8080 и выключает HTTPS, потому что сертификатов локально нет.

## Админка

Адрес — `/admin.html`. Без входа она перекинет на `/login.html`.

**Первый админ** создаётся из `.env`, когда в базе ещё нет пользователей. Пароль там хранится не открытым текстом, а хэшем. Хэш делается так:

```bash
docker compose run --rm api python -m app.auth
```

Команда спросит пароль и выведет хэш. Его нужно вставить в `ADMIN_PASSWORD_HASH`, а логин записать в `ADMIN_LOGIN`.

Что можно править:
- **О себе**: имя, тексты на двух языках, ссылки, таймлайн, плеер;
- **Проекты**: список, описания, стек, ссылки;
- **Тема**: шесть цветов для светлой и для тёмной темы;
- **Пользователи**: добавить человека с нужной ролью.

Каждый видит только те разделы, на которые у его роли есть права.

### Как устроен вход

- Пароль хранится как хэш PBKDF2-SHA256 с солью, сам пароль нигде не сохраняется.
- После входа браузер получает подписанную куку на 24 часа. JavaScript её не видит (`HttpOnly`), на другие сайты она не отправляется (`SameSite=Strict`), по обычному http не передаётся (`Secure`).
- Если сменить пароль, все старые входы перестают работать.
- Изменения принимаются только со страниц самого сайта: сервер проверяет заголовок `Origin`.
- После 5 неверных паролей подряд вход с этого адреса блокируется на минуту.

## Где лежат тексты

При первом запуске api берёт тексты и проекты из `content/about.json` и `content/projects.json` и кладёт их в базу. Дальше главная — база: правка этих файлов на уже работающем сайте ничего не изменит. Меняй всё через админку.

Локально, чтобы заново залить тексты из файлов, пересоздай базу. Осторожно: эта команда удалит все данные в ней.

```bash
docker compose -f docker-compose.yml -f docker-compose.local.yml down -v
```

Музыку и обложку для плеера положи в `nginx/html/media/` и укажи в админке путь вида `/media/track.mp3`. Ссылки на чужие сайты не принимаются.

## API

Все адреса начинаются с `/api`.

| Адрес | Что отдаёт |
|---|---|
| `GET /api/health` | Работают ли api и база |
| `GET /api/me` | Имя, тексты, ссылки, таймлайн, плеер |
| `GET /api/projects` | Проекты |
| `GET /api/theme` | Цвета светлой и тёмной темы |
| `POST /api/login`, `POST /api/logout` | Вход и выход |
| `GET /api/session` | Кто вошёл и что ему можно править |
| `PUT /api/me`, `/api/projects`, `/api/theme` | Сохранить изменения (нужен вход) |
| `POST /api/users` | Добавить пользователя (нужен вход) |

Точный формат каждого поля описан в [`docs/api-contract.md`](docs/api-contract.md).

## Тесты

```bash
docker build --target test .
```

Команда собирает образ и запускает внутри него `pytest`. Ровно то же самое делает CI на каждом pull request.

## Выкладка

Пуш в `main` запускает GitHub Actions:
1. **Проверки:** тесты, поиск случайно закоммиченных секретов (gitleaks), проверка образа на уязвимости (Trivy).
2. **Деплой:** если проверки прошли, сервер по SSH обновляет код и перезапускает только то, что изменилось.

## Безопасность

- Api работает не от root, с файловой системой только для чтения.
- У nginx отобраны лишние права Linux (capabilities). От root работает только главный процесс: без этого он не прочитает ключ сертификата. Запросы обрабатывают процессы от пользователя `nginx`.
- Версии Docker-образов, Python-пакетов и GitHub Actions закреплены точно, чтобы при сборке никто не подсунул другую версию.
- Строгая CSP: страница загружает скрипты, стили, шрифты и медиа только с этого же сайта.
- Всё, что приходит в api, проверяется на тип и длину.
