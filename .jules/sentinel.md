## 2024-10-14 - Fix DoS via Unbounded Request Body
**Vulnerability:** The application was vulnerable to a Denial of Service (DoS) attack through memory exhaustion. The `_read_limited` function used `await request.body()` to read the entire request body into memory *before* checking its size. An attacker could omit the `Content-Length` header and send a massive payload using chunked transfer encoding, crashing the server.
**Learning:** `await request.body()` in FastAPI/Starlette buffers the entire request payload into memory. It is unsafe to use this method to read untrusted input without first enforcing strict limits via chunked stream processing. Additionally, when using `request.stream()` manually to mitigate this, setting `request._body` to the accumulated bytes is critical to ensure that downstream operations relying on `request.body()` or `request.json()` do not hang or fail.
**Prevention:** Always read untrusted request bodies using `request.stream()`, accumulating the data in chunks and verifying the size limit iteratively. Ensure the `Content-Length` header is validated if present, but do not rely on it exclusively.
